# Scentdex

**What does your perfume collection say about you? That's what Scentdex tries to answer.**

## About the project

I've always been drawn to the world of perfumery — how vast and complex it is. Scentdex is my attempt to help people get to know their own olfactory profile: a way to gather your favorite scents, map them, and describe what they say about you.

The idea came while I was browsing other developers' projects for inspiration. A lot of people build a "Pokédex" — an index inspired by the Pokémon anime. I borrowed that concept as a mental starting point and pointed it at a problem I actually cared about: creating an index that maps a user's favorite scents, describes them, and offers recommendations based on that profile.

**Current status:** portfolio project, functional and tested on a physical device. Not published on the App Store — see [Roadmap](#roadmap) for where it might go next.

## Features

- **My Deck** — personal perfume collection, with a toggle between list and grid views
- **Wishlist** — perfumes you want, with a dedicated "profile match" view (compatibility percentage against your collection, shared notes, add directly to the Deck)
- **Scent Aura** — olfactory profile calculated from your collection (dominant family, signature accords, most frequent notes), with an AI-generated description and a visual "fingerprint" (radar chart)
- **Feed** — editorial content about perfumery
- **Database search** — integration with the Fragella API to add perfumes by name/brand
- **Ambient blobs** — a visual layer reactive to the colors of the user's dominant accords, with a shared transition across tabs
- **Liquid glass** — `.ultraThinMaterial` on cards and badges, consistent throughout the app

## Architecture & technical decisions

A few decisions worth explaining, because they aren't obvious at first glance:

**Ambient blobs live inside each `NavigationStack`, not behind it.**
Both `TabView` and `NavigationStack` have their own opaque backgrounds behind the content. A visual layer meant to be seen "through" the tabs has to be inserted inside each tab's navigation stack — otherwise it ends up hidden behind an opaque background that isn't obvious in the view hierarchy.

**Material (`.ultraThinMaterial`) always applied as separate `.background(material)` + `.clipShape(shape)`.**
Using `.background(material, in: shape)` only rounds the background — the content on top ends up with visible seams at the edges. Separating the two modifiers fixes it.

**My Deck grid navigation: from `NavigationLink` to a programmatic path.**
The grid (`Grid`/`GridRow`) had a bug where the "back" button advanced to the next item instead of returning to the list. The root cause was combining `NavigationLink` with `.contextMenu` on the same element — the two gestures (tap to open, long-press to remove) competed for the same touch surface, and SwiftUI sometimes misresolved which value had been activated. The fix separated the two: navigation via `path.append(perfume.id)` in a `NavigationStack(path:)`, with `.contentShape(Rectangle())` ensuring the `.contextMenu`'s touch area didn't interfere with the tap.

**Profile calculation (`ScentProfile`) with deterministic tie-breaking.**
The profile is derived by sorting accords by score, coming from a `Dictionary`. When two accords tie on score (common, since points come from discrete levels), a `Dictionary`'s iteration order isn't guaranteed between calls — this made the profile look "unstable," triggering AI description regenerations even though the underlying data hadn't actually changed. The fix adds an explicit alphabetical tie-breaker to all relevant `.sorted` calls, making the profile calculation deterministic for the same input data.

**Strict concurrency (Swift 6) requires explicit `nonisolated` in several places.**
The project uses `MainActor` isolation by default. This forces marking `nonisolated` on protocol conformances and static methods that need to be called off the main actor — including the conformances auto-generated by SwiftData's `@Model` (`PersistentModel`, `Observable`), which already come that way, and any new extension added to the models.

## Running locally

```bash
git clone <repo-url>
open Scentdex.xcodeproj
```

You'll need:
- Xcode (latest version recommended)
- An Apple developer account (a free one is enough to test on a physical device, renewing every 7 days)
- A Fragella and a Claude API key — see `Config.xcconfig.example` [TO CREATE, if it doesn't exist yet] and fill in your own keys. **Never commit real keys.**

**V2 — product exploration**

Midway through the creative process, my vision shifted from "a portfolio project" to a project with real product potential. While I mainly kept my head down delivering solid, useful functionality, I've got a set of ideas to complement the user experience and give this project what it takes to become a product:

- **Login management with Firebase** — user accounts and authentication
- **PriceRunner function** — track and compare the best prices and deals for your favorite perfumes
- **Reverse recommendation** — based on the *opposite* of the user's collection, giving the user a chance to explore and expand their scent-note range
- **Social** — share your profile with friends; an interesting way to understand another person's profile and get a solid recommendation for a gift
- **Season recommendation** — by adding fragrance concentration, surface the best recommendations and suggestions for new perfumes at the start of each new season
- **Brand partnerships** — down the line, possible partnerships with brands and stores for better deals
